هذه معالجة للفشل الحقيقي في المحادثة، دون إعادة بناء طبقة العقل.

## السبب المثبت

وصلت رسالة «مرحبا» الحقيقية عند `2026-09-10T06:47:46.384607Z`،
وبدأت معالجتها عند `06:47:47.661372Z`. انتهت الدفعة إلى
`HUMAN_REQUIRED / REPEATED_REQUIREMENT_EXTRACTION_FAILURE`.
كانت الحالة المحفوظة `BOOK_SERVICE / BOOKING`، والمتطلب
`intent_confirmation` بعدّاد 4. التحويل السابق الذي حدث في 9 سبتمبر
بقي محفوظًا بحالة `RETURNED_TO_AI`؛ لم يُحذف أي دليل.

العدّاد كان يقارن المتطلب والقيمة فقط، دون عمر المحاولة أو الحلقة الحوارية.
التحية في حجز نشط لم تصل إلى الرد الخاص بالتحيات. وكان التحويل الأولي
بسبب العداد يمنع تفسير دور الرسالة، حتى عند كونها سؤالًا جانبيًا.
كذلك كان السؤال الجانبي قد يرث عددًا بلغ الحد مسبقًا فيتحول دون محاولة فاشلة جديدة.

## التغيير المحدود

- تمييز التحية الكاملة قبل احتساب الفشل، مع إبقاء الرسائل المختلطة مثل «هلا، باجر» قابلة لاستخراج الحقائق.
- التحية توقف حلقة المحاولات وترد، مع حفظ هدف الحجز والحقائق الصالحة وعدم منح تأكيد أو صلاحية أداة.
- ربط العدّاد بالمتطلب والهدف والخدمة، وبوجود توضيح سابق نشط، وبحد الخمول الحالي نفسه: 30 دقيقة.
- الأسئلة الجانبية تبدأ حلقة محاولات جديدة؛ الحد الأصلي 3 باقٍ ولم تُزل حماية التحويل.
- السماح بتفسير الدور قبل اعتماد تحويل سببه الوحيد فشل الاستخراج الأولي. بقية حواجز الأمان والتحويل البشري ما زالت نهائية.
- «خلاص ما أبي أحجز» توقف متابعة الطلب وتمسح عدّاده، دون إلغاء حجز فعلي.

لا migration جديدة، ولا dependency، ولا تعديل لصلاحيات أو RLS أو اتصال Meta.
مسار استعادة المحادثة هو `dabbir_return_conversation_to_ai` الرسمي، الذي
يتحقق من هوية المستخدم وعضويته وصلاحيتي الرد وإدارة التحويلات، ويحفظ سجل التحويل.
لم يُستبدل هذا المسار بتعديل يدوي للجداول أو انتحال هوية مستخدم.
