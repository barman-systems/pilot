# العودة المباشرة إلى AI بعد إصلاح التحية

أثناء استعادة المحادثة الحقيقية بعد نشر `0ae7e93`، أظهرت الواجهة زر
«استلام يدوي» فقط للحالة `action_required`. زر العودة الموجود كان محصورًا
في `human_active`، رغم أن `dabbir_return_conversation_to_ai` الرسمي يدعم
التحويل المنتظر `QUEUED`. أُلغي اقتراح الاستلام اليدوي ولم يُنفَّذ.

أُضيف زر «إعادة إلى DABBIR» مستقل للحالة `action_required` فقط، ويطلب
تأكيد العودة ثم يستدعي `/api/chat-control` بالفعل `return_to_ai`.
يبقى زر الاستلام اليدوي الأصلي منفصلًا، ومحرر الرد اليدوي مقفلًا حتى
الاستلام الصريح. لا تتغير صلاحيات المالك أو قواعد RLS أو RPC أو تاريخ التحويل.
تبديل المحادثة أثناء التأكيد يلغي الطلب حتى لا يُطبّق على عميل آخر.

أضيفت ثمانية اختبارات تشغيلية للواجهة: العربية والإنجليزية، إخفاء الزر
عن الحالة النشطة للـAI، الاستعادة السابقة، الاستلام اليدوي المنفصل، إلغاء
التأكيد، تبديل المحادثة، وفشل الصلاحية دون ادعاء النجاح.
اختبارات الواجهة وحدود العودة وRLS: **19/19**.
يخضع التغيير أيضًا للمجموعة الكاملة وCI وفحص Production قبل اعتماد النتيجة.

هذه إضافة لازمة لاستعادة المحادثة بالطريق المطلوب مباشرةً؛ لا إعادة بناء
للعقل ولا تغيير إضافي في منطق المتطلبات أو قاعدة البيانات.
