## المنفذ

أضيف مُصدّر تقني اختياري بعد عودة سجل ميزانية الذكاء الاصطناعي بنجاح، مع الحفاظ على استجابة السجل الأصلية. يرسل بيانات محدودة عن النتيجة والمزوّد والنموذج والتكلفة والتوكنات المتاحة. تظل التكلفة أو التوكنات غير المتاحة فارغة، ولا تُسجّل كصفر.

يستخدم المُصدّر واجهة OTLP/HTTP JSON الحالية في Langfuse مع الترويسة `x-langfuse-ingestion-version: 4`، وليس واجهة ingestion القديمة الجاري إيقافها.

يمكن الإرسال مباشرة إلى Langfuse، أو عبر مهمة Trigger.dev مع مفتاح لمنع إنشاء تشغيل مكرر، وثلاث محاولات كحد أقصى، وعامل micro واحد، وحد تنفيذ 10 ثوانٍ. مهمة Trigger تنقل السجل التقني فقط؛ لا تملك صلاحيات حجز أو إرسال واتساب أو كتابة في قاعدة البيانات.

## حدود ما أُنجز

هذا **حدث إنهاء سجل الميزانية** وليس تتبعًا كاملاً لكل استدعاء للنموذج أو أدوات الوكيل. لا يثبت تنفيذ الحجز، ولا يقيس زمن استجابة النموذج. أُبقي نوع الحدث `event` وتوقيت البداية والنهاية متساويين حتى لا نخترع زمن تنفيذ. التكلفة المسجلة بيانات وصفية وليست بديلاً عن دفتر التكلفة الموثّق أو فاتورة المزوّد.

لا يوجد تغيير في قاعدة البيانات أو واجهة العميل أو المزوّدين أو منطق الحجز أو إجراءات الاعتماد. سجل دبّر الحالي هو المرجع. فشل طلب إضافة المهمة إلى Trigger لا يتحول إلى نجاح وهمي، ولا نضمن عدم فقد سجل المراقبة قبل قبول المهمة. لا تؤدي إعادة المحاولة إلى إعادة تنفيذ أعمال العميل.

## الخصوصية وضبط الإنفاق

كلا الربطين متوقف افتراضيًا. لا تُرسل نصوص المحادثة أو أسماء العملاء أو أرقامهم أو إيميلاتهم أو البيانات الخام أو نصوص الأخطاء. المعرّفات مشتقة باستخدام HMAC، وتُعاد تصفية البيانات عند وصولها إلى العامل. عناوين Langfuse محصورة في النطاقات السحابية الرسمية، وإعادة التوجيه ممنوعة. مهلة طلب المراقبة داخل التطبيق لا تتجاوز 750 ملي ثانية عند تفعيله؛ لا توجد مكالمة خارجية عند تعطيله.

نسبة أخذ العينة الافتراضية 10%؛ هي لتقليل الحجم وليست سقفًا شهريًا مضمونًا. الاختيار المالي المطلوب: Langfuse Hobby المجانية وTrigger Free فقط، دون ترقية أو تفعيل تجاوزات مدفوعة. لم يُنشأ اشتراك مدفوع. تكاليف Vercel والنماذج والخدمات القائمة منفصلة عن مجانية الأداتين.

## متطلبات التفعيل غير المنجزة

يجب أن تكون الحسابات والمشروعات تحت ملكية المستخدم، ثم توضع المفاتيح في مخازن الأسرار، لا في المحادثة أو GitHub source.

في Vercel Preview فقط في البداية:

- `LANGFUSE_PUBLIC_KEY` و`LANGFUSE_SECRET_KEY` و`LANGFUSE_BASE_URL` من مشروع Langfuse نفسه.
- `DABBIR_LANGFUSE_ENABLED=1` و`DABBIR_TELEMETRY_SAMPLE_RATE=1` لاختبار اصطناعي محدود.
- `TRIGGER_SECRET_KEY` الخاص ببيئة التطوير عند تشغيل اختبار محلي، أو بيئة الإنتاج في Trigger بعد نشر العامل.
- `DABBIR_TRIGGER_ENABLED=1` فقط بعد إثبات نشر العامل في بيئة المفتاح المختار.

في بيئة عامل Trigger:

- مفاتيح Langfuse و`LANGFUSE_BASE_URL` و`DABBIR_LANGFUSE_ENABLED=1` فقط.
- لا تنسخ مفاتيح Supabase أو WhatsApp أو النماذج إلى العامل.

لتجهيز الحزمة المنفصلة:

```sh
cd integrations/trigger
npm install --ignore-scripts
# إنشاء ملف القفل ومراجعته وإيداعه قبل أول نشر فعلي.
# TRIGGER_PROJECT_REF: معرّف المشروع الحقيقي، وليس رمزًا سريًا.
# تُستخدم مصادقة Trigger الرسمية؛ لا تُحفظ بيانات الدخول في المستودع.
npm run dev
```

لم تُنفذ أوامر الدخول أو النشر السحابي. يلزم بعد ربط الحسابات: اختبار اصطناعي، إثبات ظهور الحدث في Langfuse، إثبات نجاح التشغيل في Trigger، اختبار رفض البيانات وإعادة المحاولة، ثم اجتياز CI والمراجعة قبل تفعيل الإنتاج. يمكن تعطيل التصدير فورًا بـ`DABBIR_LANGFUSE_ENABLED=0` دون تغيير تشغيل دبّر.

## أدلة الاختبار

نجحت محليًا 29 حالة اختبار مستقلة للمُصدّر، على Node 22.16.0 وبشبكة وهمية؛ لم تُرسل بيانات إلى المزوّدين. أضيفت أربع حالات لربط دفتر الميزانية، ليشغّلها CI الكامل بمكتبات المشروع الحقيقية. أضيف فحص مستقل لتثبيت SDK الخاص بـTrigger والتحقق من تسجيل المهمة وإعدادها دون مفاتيح سحابية. هذه الفحوص لا تعادل نشرًا أو تشغيلًا سحابيًا حيًا.
