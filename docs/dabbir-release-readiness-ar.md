# جاهزية دبّر للتجربة المغلقة

**الحالة:** جاهز كتجربة مغلقة مع مالكي متاجر محددين، وليس جاهزًا بعد للإطلاق العام في App Store.

## ما أصبح جاهزًا

يدعم تطبيق iPhone مسارًا كاملاً لصاحب متجر صغير: إنشاء متجر باسم واحد، إضافة منتجات، البحث عنها، تسجيل بيع سريع، اختيار طريقة الدفع، منع البيع فوق المتاح، تسجيل استلام بضاعة، وتنفيذ جرد يدوي موثق. تحفظ كل عملية بيع عناصرها وأسعارها وقت البيع، ويُسجَّل كل تغيّر في المخزون كحركة قابلة للتدقيق. تعرض لوحة اليوم المبيعات والتحصيل والمصروفات والمبالغ الآجلة من دون تقديم الفرق بينها كربح محاسبي.

يستخدم المساعد الذكي حقائق تشغيلية موثقة لليوم في دبي، بما فيها المبيعات والتحصيل والمصروفات والمنتجات منخفضة المخزون. لا يملك المساعد تنفيذ عمليات كتابة ولا يصرح بأنه نفذ إجراء لم يحدث.

## التحقق المنجز

| مجال التحقق | النتيجة |

| اختبارات المشروع | 590 اختبارًا ناجحًا، من دون فشل أو تخطٍّ. |
| صياغة JavaScript | ناجحة. |
| TypeScript لتطبيق iOS | ناجح. |

| صفحات قانونية عامة | صفحات الخصوصية والشروط والدعم متاحة في الإنتاج. |

## قرارات جودة متعمدة

يعتمد إصدار v1 على iPhone أولًا. لا نربط قارئ باركود أو طابعة أو جهاز دفع قبل تحديد الطراز الفعلي ومزود التكامل. يظل عنوان API مطلوبًا صراحة في البيئة، ويُثبت في ملفات بناء EAS للنسختين التجريبية والإنتاجية؛ التطبيق يفشل برسالة مفهومة بدل أن يرسل بيانات المتجر إلى عنوان غير محدد.

ظهر تدقيق npm لعميل Expo تحذيرات معتدلة مرتبطة بسلسلة أدوات Expo/Xcode، والحل الآلي المقترح يتطلب تغييرًا كسريًا غير آمن في إصدار Expo. لا تؤثر هذه الحزم في منطق التشغيل داخل التطبيق، لذلك لم تُطبق ترقية قسرية قد تكسر البناء. تدقيق اعتماديات خادم الإنتاج لم يعثر على ثغرات عالية.

## ما يمنع الإطلاق العام فقط

يتطلب الإطلاق في App Store حساب Apple Developer مسجلاً، تطبيق App Store Connect، منتج اشتراك فعلي إذا تقرر تفعيله، شهادات Apple المطلوبة، بناء موقّع وTestFlight، وفحص على iPhone حقيقي. كما يلزم اختبار تجريبي مع متاجر حقيقية قبل تمكين واتساب أو ربط جهاز كاشير Mini أو بوابة دفع. تغييرات تطبيق iOS لا تتطلب نشر واجهة Vercel؛ آخر deployment مرتبط بالـ commit الجديد أُوقفته قاعدة مسار النشر لأنه تغيير native/mobile فقط، بينما بقي آخر نشر إنتاجي للويب بحالة READY.

## أفضل خطوة تالية

ابدأ بتجربة مغلقة مع 3 إلى 5 متاجر. تقيس التجربة زمن تسجيل البيع، دقة الكمية، تكرار استخدام لوحة اليوم، وأسئلة المساعد. بعد ظهور جهاز الكاشير Mini الفعلي، نحدد آلية الربط الدقيقة: واجهة سحابية من المزود، Bluetooth، أو استيراد مبيعات.
